## 摘要

本文提出了 **JitterSketch**，这是首个专门用于检测抖动流的基于 Sketch 的算法。网络抖动定义为网络流内数据包到达时间的突然波动，严重影响实时应用的服务质量 (QoS)。

**核心贡献：**
1. 采用新颖的三阶段结构，高效过滤不频繁和稳定的流
2. 在召回率和精确率上比基线方法提高高达**50 个百分点**
3. 保持高处理吞吐量，达到基线的**10 倍**
4. 在 QoS 仿真系统中验证了实际效果

---

## 1. 研究背景与动机

### 1.1 问题背景

- 实时应用（在线游戏、视频会议、VoIP）对网络抖动高度敏感
- 传统抖动检测方法关注宏观的端到端或逐跳延迟变化
- 忽略了特定流内部发生的细粒度抖动

### 1.2 关键概念：IFPD (Intra-Flow Packet Delay)

**定义：** 流内连续数据包之间的时间间隔
$$D_i = t_i - t_{i-1}$$

**IFPD 抖动的三种类型：**
| 类型 | 特征 | 原因 |
|------|------|------|
| **减速抖动 (Deceleration)** | IFPD 突然增加 | 网络拥塞 |
| **加速抖动 (Acceleration)** | IFPD 突然减少 | 拥塞缓解/路由改进 |
| **混合抖动 (Mixed)** | 上述两种模式组合 | 复杂网络状况/APT 攻击 |

### 1.3 应用场景

1. **QoS 优化** - 视频流、游戏、VoIP 需要稳定的延迟
2. **网络拥塞检测** - 减速抖动是拥塞的早期指标
3. **APT 攻击检测** - "低慢速"攻击产生特征性的复合抖动模式

### 1.4 现有方法的局限

| 方法类型 | 代表工作 | 局限性 |
|----------|----------|--------|
| 端主机方法 | RTT/OWDV 测量 | 无法定位具体故障节点 |
| 特定协议方法 | RTP/RTCP 分析 | 依赖特定协议，缺乏通用性 |
| 网络内方法 | DelaySketch, FD-Filter | 仅估计 IFPD，不检测抖动模式 |

## 2. 问题定义

### 2.1 抖动流的三个判定条件

对于流 $F_x$，判定为抖动流需满足：

**(1) 显著的相对变化** (给定抖动因子 $k > 1$)：
- **减速**：$D_{i+1} \geq k \cdot D_i$
- **加速**：$D_{i+1} \leq \frac{1}{k} \cdot D_i$

**(2) 有界的绝对变化**：
$$T_{min} < |D_{i+1} - D_i| < T_{max}$$
- 下界过滤噪声
- 上界区分抖动与空闲期

**(3) 最小流大小**：
$$f_x \geq C$$
- 过滤短生命周期的流，确保统计可靠性

### 2.2 为什么这样定义？

- IFPD 分布呈现**重尾特性**（非均匀、非正态）
- 需要使用**相对定义**而非固定阈值
- 采用 IQR (Interquartile Range) 方法进行异常检测

## 3. JitterSketch 设计

### 3.1 整体架构

```
                    ┌─────────────────────────────────────────────────┐
    输入包 (x,t) ──►│           反向查找 (Stage 3→2→1)               │
                    └─────────────────────────────────────────────────┘
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
              ┌──────────┐     ┌──────────┐     ┌──────────┐
              │ Stage 1  │     │ Stage 2  │     │ Stage 3  │
              │ Micro    │────►│ Stable   │────►│ Jitter   │
              │ Filter   │     │ Cache    │     │ Detector │
              └──────────┘     └──────────┘     └──────────┘
                   │                │                │
                   ▼                ▼                ▼
               微流过滤          稳定流缓存       抖动检测上报
```

### 3.2 Stage 1: Micro Filter (微流过滤器)

**目的：** 过滤低频流，减少对后续阶段的压力

**数据结构：**
- $w$ 个桶的数组
- 每个桶存储：指纹 ($fp$, 如 8 位) + 频率计数器 ($freq$)

**操作逻辑：**

| 操作 | 描述 |
|------|------|
| **lookup1** | 指纹匹配则 $freq+1$，达到阈值 $C$ 则晋升 Stage 2 |
| **insert1** | 空桶则插入；占用桶则 $freq-1$，归零则清空 |

**优化 (JitterSketch-Opt)：** 使用 $v$ 个哈希函数提高精度

### 3.3 Stage 2: Stable Cache (稳定流缓存)

**目的：** 监测通过 Stage 1 的流，检测潜在抖动

**数据结构：**
- $s$ 个桶的数组
- 每个桶存储：长指纹 (16 位) + 时间戳 + 小 IFPD (4 位)

**操作逻辑：**

| 操作 | 描述 |
|------|------|
| **lookup2** | 指纹匹配则计算当前 IFPD，检查抖动条件 |
| **抖动检测** | $\frac{当前 IFPD}{存储 IFPD} \geq k$ 或 $\leq \frac{1}{k}$ |
| **insert2** | 无条件覆盖，晋升到 Stage 3 |

### 3.4 Stage 3: Jitter Detector (抖动检测器)

**目的：** 精确监测并上报抖动事件

**数据结构：**
- $l$ 个桶，每桶 $d$ 个条目
- 每个条目存储：**完整流键** + 时间戳 + IFPD

**延迟公平替换策略 (Delay-Fair Replacement)：**
$$\text{eviction\_metric} = \frac{t - entry.timestamp}{entry.IFPD}$$

解释：该值表示"预期错过的包到达数"，优先替换最可能不活跃的流。

### 3.5 运行示例

| 案例 | 描述 |
|------|------|
| Case 1 | $e_1$ 频率达阈值 20，晋升 Stage 2 |
| Case 2 | $e_5$ 哈希冲突，计数归零被驱逐 |
| Case 3 | $e_6$ 使用 2 个哈希函数，找到空位插入 |
| Case 4 | $e_9$ 在 Stage 2 检测到 IFPD=50 过大，晋升 Stage 3 |
| Case 5 | $e_{10}$ 触发减速抖动 (30/5=6>4)，上报事件 |
| Case 6 | $e_{16}$ 触发加速抖动 (9<45/4)，上报事件 |

## 4. 实验评估

### 4.1 实验设置

**平台：** Intel i7-13700KF, 32GB DRAM

**数据集：**
| 数据集 | 包数量 | 流数量 | 检测到的抖动事件 |
|--------|--------|--------|------------------|
| CAIDA | 1.1M | 110K | 55K 减速 / 55K 加速 |
| MAWI2020 | 10M | 1.9M | 354K 减速 / 1.08M 加速 |
| MAWI2025 | 5M | 1.1M | 411K 减速 / 411K 加速 |

**基线方法：** DelaySketch, FD-Filter (均增强哈希表)

**评估指标：**
- 精确率 (PR)、召回率 (RR)、F1 分数
- 吞吐量 (TP, Mpps)

### 4.2 主要结果

#### 减速抖动检测

| 方法 | F1 分数 (MAWI2020, 200KB) | 吞吐量 |
|------|--------------------------|--------|
| JitterSketch | 0.99 | 13.48 Mpps |
| JitterSketch-Opt | - | 8.01 Mpps |
| DelaySketch | 0.65 | 3.12 Mpps |
| FDFilter | 0.20 | 1.31 Mpps |

#### 加速抖动检测

| 方法 | 召回率 (MAWI2020, 200KB) | F1 分数 (CAIDA, 100KB) |
|------|-------------------------|------------------------|
| JitterSketch-Opt | 0.997 | 0.98 |
| DelaySketch | <0.8 | 0.68 |
| FDFilter | <0.8 | 0.58 |

#### 混合抖动检测

| 方法 | 召回率 (MAWI2020, 600KB) |
|------|-------------------------|
| JitterSketch | 0.996 |
| FDFilter | 0.32 |
| DelaySketch | 0.82 |

### 4.3 参数调优

| 参数 | 含义 | 最优值 |
|------|------|--------|
| $r_1$ | Stage 1 内存比例 | 0.5 |
| $r_2$ | Stage 2/3 内存比 | 0.5 |
| $d$ | Stage 3 桶深度 | 4 (减速/加速), 6 (混合) |
| $v$ | Stage 1 哈希函数数 | 2 (减速/混合), 3 (加速) |

## 6. 理论分析 (附录 A)

### 6.1 误差分析

**Stage 1 (频率计数器)：**
- 高估概率：$HighBias_{S1} \leq \frac{1}{(2^{m_1}-1)^{c-1}}$
- 低估概率：$LowBias_{S1} \leq 1 - \frac{1}{c(2^{m_1}-1)^{c-1}}$

**Stage 2 (配对缓存)：**
- **无过估计**（命题 A.2）
- 覆盖遗漏：$LowBias_{S2} \leq \frac{1}{2^{m_2}}$

**Stage 3 (IFPD 检测器)：**
- **无过估计/低估**，仅有遗漏
- 遗漏概率：$P_{miss}^{(3)} \leq \frac{r_b^+}{\lambda_x}$

## 7. 总结与评价

### 7.1 核心贡献

1. **问题创新**：首次将 IFPD 抖动细分为减速、加速、混合三种类型
2. **算法创新**：三阶段级联架构，资源高效利用
3. **性能优势**：精确率和召回率提升 50 个百分点，吞吐量提升 10 倍
4. **实用价值**：在 QoS 系统中验证了实际效果

### 7.2 优点

- 轻量级设计，适用于高速网络核心设备
- 协议无关，通用性强
- 支持复杂抖动模式检测（如 APT 特征）
- 延迟公平替换策略，避免对大 IFPD 流的偏见

### 7.3 潜在局限

- 需要手动调节参数 (k, C, Tmin, Tmax)
- 对哈希冲突敏感（虽然 JitterSketch-Opt 有所改善）
- 理论分析基于泊松到达假设

### 7.4 适用场景

- 网络拥塞早期检测
- QoS 保障系统
- APT 攻击检测（低慢速通信模式）
- 实时应用性能监控
