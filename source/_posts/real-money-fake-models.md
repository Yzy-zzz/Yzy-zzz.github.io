## 1. 摘要（Abstract）与核心贡献（Core Contribution）

### 1.1 一句话总结

**论文要解决的问题是：当一个第三方 LLM API 宣称自己提供“GPT-5 / Gemini / DeepSeek 的官方同款模型”时，用户如何知道自己真正买到的是哪个模型、得到的是否是同等能力？作者通过生态调查、效用与安全评测、模型指纹、分布检验和元数据分析，建立了一套黑盒审计证据链。**

也可以把它理解成 AI 基础设施中的“**货不对板检测**”：用户购买的是某个模型的服务承诺，而审计员只能看见输入、输出、调用时间和计费信息，无法直接登录服务商的后端。

### 1.2 核心贡献（Contribution List）

1. **首次针对 Shadow API 生态进行有范围定义的系统性调查。** 作者从论文代码仓库和 API 端点反向搜索，找到 **17 家**符合定义的服务商，并识别出 **187 篇**使用这些服务的学术论文，其中 **116 篇**已经发表于同行评议会议或期刊；相关统计时间点为 2025-12-06（§3，Figure 2）。
2. **证明“能调用、能答题”不意味着“与官方 API 等价”。** 在 **3 家代表性服务商 A/E/H × 8 个被宣传的模型 = 24 个端点**上，作者发现科学推理、医疗法律问答和越狱安全表现均存在偏离；敏感任务上部分准确率差距达到 **47.21 个百分点**（§4，Figures 3–6）。
3. **将行为异常推进到有条件的模型身份判断。** 结合 **LLMmap 模型指纹**、**MET 输出分布相等性检验**、**受控替换试验**和**时延/token 元数据**，发现 **11/24（45.83%）端点指纹核验失败**，另有 **3/24（12.50%）**匹配到声称的模型但指纹距离超出阈值；部分端点的指纹与具体替代模型一致（§5，Tables 3–6）。

### 1.3 最值得先记住的三组数字

| 维度 | 关键结果 | 正确理解 |
|---|---:|---|
| 生态普及 | 17 家服务、187 篇使用论文 | **生态层面**的调查，不等于 17 家全部做过性能实测 |
| 模型身份 | **11/24 = 45.83%** 指纹未通过 | **被测端点**的比例，不是市场上 45.83% 的服务商都在故意欺骗 |
| 任务表现 | Gemini-2.5-flash：官方 MedQA **83.82%**，影子端点平均约 **36.95%** | 两者相差约 **46.87 个百分点**；最大单端点差距为 **47.21 个百分点** |

这篇论文最重要的科学立场在于区分：**行为不同（observed inconsistency）≠ 一定换模（model substitution）≠ 已经证明经营者有主观欺骗意图**。作者把“deceptive model claim”限定为商业宣传的模型身份与指纹证据一致支持的替代身份之间存在不符，并明确不对经营者意图作司法意义上的定性（§2.3）。

## 2. 引言（Introduction）：问题背景与研究动机

### 2.1 问题定义（Problem Definition）

主流闭源大模型常通过官方 API 提供能力，但实际研究者可能遇到**价格较高、支付不便、地理区域限制**等障碍。于是出现所谓的 Shadow API：它用兼容官方 SDK 的接口和模型名称对外售卖调用额度，声称用户可以像使用官方 API 一样使用模型（Figure 1）。

![论文 Figure 1：Shadow API 生态示意图](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/figure1_ecosystem.png)

*图 1（原文 p.1）：用户绕过直接访问障碍，转向第三方中转服务；图中的虚线承诺并不能证明请求实际发给了哪个后端。*

论文关注的不是单纯的“模型输出是否准确”，而是一个更根本的安全属性：**模型来源完整性（model provenance integrity）**。

设某服务对外宣称的模型标识为 $m_c$，实际产生响应的后端为 $m_b$。理想情况下，服务提供方应该维持一种可核验的绑定：

$$
\text{Advertised Model } m_c \quad\longleftrightarrow\quad
\text{Backend Serving the Request } m_b.
$$

当服务商不公开上游路由时，用户只能观察到输入 $x$ 与返回文本 $y$，无法直接确认这一绑定。因此至少会出现三种不同风险：

- **身份风险**：请求并未由被宣传的模型处理；例如买的是高端推理模型，指纹却像小型开源模型。
- **行为风险**：即使调用了原模型，服务商仍可能通过默认思考预算、提示词预处理、截断、重试或参数修改改变其行为。
- **科研风险**：论文把通过不明后端测得的成功率、幻觉率或安全性归因于某个知名模型，导致结论难以被其他人复现。

**学术意义**：如今很多安全、Agent、评测和医学 AI 研究都把在线大模型当成“实验仪器”。如果这台仪器的型号无法确认，那么“控制变量”和“可复现性”的前提就会动摇。  
**工程意义**：价格、延迟和 API 响应格式并不能保证服务质量；尤其在医疗、法律、生产系统等场景，静默替代造成的风险可能被用户完全忽略。

### 2.2 现有方法的局限（Limitations of Prior Work）

**路线 A：只看任务基准（benchmark-only audit）。** 以前很多评估只比较多个 API 的 Accuracy、成功率或延迟。这种方法易部署、与任务直接相关，但有一个根本盲区：**不同模型完全可能在简单题上拿到差不多的分数**。因此，“分数接近”无法证明“是同一个模型”；“分数下降”同样无法证明“一定换了模型”，也可能只是推理参数、上下文长度或解码方式不同。

**路线 B：只做模型指纹或模型相等性检验。** 论文借鉴了两类已有工具：

- **LLMmap**（Pasquini 等，USENIX Security 2025）：通过对模型发送具有辨识度的提示词来估计其模型身份，适合回答“**它更像谁？**”。
- **Model Equality Testing（MET）**（Gao 等，ICLR 2025）：把两个 API 输出当作样本分布，进行统计检验，适合回答“**在这个任务分布上，它们是否可区分？**”。

它们各有盲点。指纹可能仍然识别为正确模型，但推理能力因为推理预算不足而下降；MET 可以发现分布不同，却不一定知道实际后端是谁。反过来，如果一个替代模型模仿得足够像，MET 也可能因为检验功效不足而不拒绝原假设。

**本文的切入点**不是发明一个新的损失函数，而是把生态测量、任务表现、身份识别和统计检验放在同一审计流程中，避免任何单一指标被过度解释。

### 2.3 本文思路（Overall Idea）

作者明确提出三个研究问题：

| 研究问题 | 想回答什么 | 主要证据 |
|---|---|---|
| **RQ1：生态有多大？** | 有多少服务商、它们是否已进入学术研究？ | 文献代码仓库、端点 URL、引用数、GitHub stars、合规披露（§3） |
| **RQ2：行为是否一致？** | 在相同任务中，影子 API 能否复现官方表现？ | 数学/科学、医学/法律、越狱攻击和有害性评分（§4） |
| **RQ3：后台到底是谁？** | 能否找到与替代模型一致的证据？ | LLMmap、MET、受控实验、时延和 token 波动（§5） |

**问题 → 方法 → 验证**的主线为：先确认真实世界中存在值得审计的对象，再量化“输出行为不等价”，最后尝试判断“不等价”是否与后台模型身份有关。

## 3. 方法论深度解析（In-depth Methodological Analysis）

> 🔬 本文是**多维黑盒审计框架**，不是一个单独的神经网络架构。理解它的关键，是弄清楚每一种观测究竟能支持什么级别的结论。

### 3.1 整体架构（Overall Architecture）

论文没有传统意义上的“Encoder → Attention → Decoder”模型结构图；**Figure 1** 是应用生态示意，真正的技术架构由 §3—§5 的连续审计流程组成。可以把流程重建为以下六步：

```text
学术论文/开源代码仓库
         │ 搜索 API base URL、判断是否符合 Shadow API 定义
         ▼
发现 17 个服务商 ──► 按热度、可访问性、模型覆盖选出 A/E/H
         │
         ▼
       8 个模型标识 × 3 个服务商 = 24 个被审计端点
         │
         ├────────── 官方 API（对照组）
         │                 │ 同一数据集、尽量一致的 prompt/参数
         └────────── Shadow API（实验组）
                           │
              ┌────────────┼─────────────┐
              ▼            ▼             ▼
          效用与安全      主动指纹检测   MET 分布相等性检验
          Accuracy /     LLMmap：最像谁？  H0：分布是否相同？
          Harmfulness         │             │
              └────────────┬─┴─────────────┘
                           ▼
                  元数据交叉验证：时延、token
                           │
                           ▼
              受控真值试验 + 端点级风险综合判断
                           │
                           ▼
        结论：行为偏离 / 身份替代证据 / 检验局限 / 复现建议
```

这个框架的设计核心是**证据分层**：

1. **Utility/Safety** 告诉你“产生了什么后果”，但无法单独找出幕后模型。
2. **LLMmap** 给出“特定候选模型身份”的概率性线索，但并非物理服务器证明。
3. **MET** 检查两个输出分布是否可区分，可补充身份检验之外的行为差异。
4. **Metadata** 发现疑似多级路由、重试或截断的迹象，但不能仅据波动判断替换。
5. **Controlled Testbed** 在知道真实后端时估计检验器的误报/漏报，避免“拿不准确的尺子量别人”。

与单一 benchmark 论文相比，这种设计的宏观变化是：**研究对象从“模型能力”转向“服务对模型身份与行为的承诺是否可信”**。这是论文方法论上真正值得学习的地方。

### 3.2 核心组件/模块拆解（Core Component Breakdown）

#### 3.2.1 模块一：Shadow API 发现与实验对象筛选

**输入**：学术会议论文、论文关联的 GitHub 仓库、代码中实际调用的 `base_url`、与模型名称相关的 API 请求配置。  
**输出**：17 家符合预定义标准的第三方服务商，及其中 3 家用于深度实验的服务商 A、E、H。

**内部机理与数据流（§3.1）**：

1. 以 **ICLR 2024** 和 **ACL 2024** 为种子，共获得 **2,113 篇有代码的论文**。
2. 从这些代码中发现 **92 个使用 LLM API** 的项目；其中 **21 篇（21/92 = 22.82%）**至少涉及一个符合标准的 Shadow API 端点。
3. 以这些端点 URL 为线索，反向搜索其他公开仓库，再发现新的端点，循环直至没有新端点被找到。
4. 使用**预先定义的结构性条件**筛选：中间商凭据、上游路由不透明、绕过区域访问限制；并排除官方渠道、透明路由平台和使用用户自带密钥的网关。
5. 根据引用数、GitHub star、端点可用性及模型覆盖率选取 A、E、H；**这三家不是随机抽样**。

![论文 Figure 2：生态调查结果](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/figure2_landscape.png)

*图 2（原文 p.5）：(a) 187 篇论文的发表 venue；(b) 作者地理分布；(c) 各个匿名服务商相关项目的引用量与 star。图中高引用、高 star 是“使用广泛”的证据，而不是“服务可信”的证据。*

**设计动机**：不直接搜索广告页或“谁便宜”来定义研究对象，而是从**学术代码实际使用痕迹**出发，可更直接地检验科研可复现性问题；先定义纳入规则，避免按照结果好坏选择样本。

**要注意的分母问题**：22.82% 是 **21/92 个 API 使用项目**，**不是**所有 2,113 篇有代码论文的 Shadow API 使用率；扩展搜索得到的 187 篇也不是从一个有明确定义的总体中随机抽取。把这些数字说成“全部学术论文有 22.82% 使用影子 API”是不成立的。

#### 3.2.2 模块二：任务行为审计——Utility 与 Safety 两条线

**输入**：同一批问题 $x$、官方和影子端点、尽量可对齐的模型参数；数据集覆盖 AIME 2025、GPQA Diamond、MedQA（USMLE）、LegalBench SCALR、JailbreakBench、AdvBench-50。  
**输出**：准确率、逐题正确性一致性、越狱响应的有害性评分及实验方差。

**内部机理**分成两种性质不同的测试：

- **效用评测**：AIME 测高难度数学推理；GPQA 测研究生/博士级科学知识与推理；MedQA、LegalBench 用于检测专业高风险场景的能力是否退化。统一任务 prompt，对多次调用结果统计准确率及标准差。
- **安全评测**：分别使用 GCG、Base64、Combination、FlipAttack 四类攻击，另加“无攻击”对照；用基于 **GPT-4o-mini** 和 **StrongREJECT rubric** 的评审器评估生成内容是否有效且有害。**评分越高，表示响应越有害、此维度安全性越差**。

此处安全实验不是在测试“是否泄露用户数据”“API 密钥安全”或“合规程度”；它只考查**遭遇恶意请求时的输出行为**。因此不能把本节的“安全性”外推为全部安全属性。

**为何设计双线评测？** 原因是 Shadow API 可能同时破坏**能力可复现性**和**风险评估可复现性**。对科研而言，两种方向都危险：

- 如果影子端点的有害性**高于**官方值，研究者可能**高估**某个越狱攻击针对官方模型的成功程度。
- 如果影子端点的有害性**低于**官方值，研究者可能**低估**官方模型在该攻击下的实际风险。

因此，本文关注的是“**对官方端点的偏离**”，而不是假设官方端点永远更好、更安全。

#### 3.2.3 模块三：身份识别与互补验证（全篇技术核心）

**A. LLMmap：主动指纹识别（§5.1）**

- **输入**：一个未知后端的 API、精心设计的辨识性提示词集合、已知模型的指纹参考库。
- **输出**：最匹配的候选模型及其与参考库的欧氏距离 $D$。
- **内部机制**：不同模型对特定提示词在回答风格、结构、偏好与内容上具有可区分的稳定模式。主动询问一组“最能区分模型”的问题，比泛泛抽几条普通用户问答更高效。LLMmap 对这些响应进行特征化并与参考指纹比较；本文按原框架配置扩展了模型参考库，见 Appendix H 的 **Table 17：共 60 个候选模型（42 个既有模型 + 18 个新增模型）**。
- **设计目的**：检测“宣传 GPT-5，输出却与 GLM-4-9B 更像”这一具体身份不符的线索，而非仅报告准确率掉了多少。

**B. MET：Model Equality Testing（§5.2）**

- **输入**：针对相同任务提示词，分别从官方端点与影子端点采集的多次输出样本。
- **输出**：两样本检验的统计判断：`Reject`（拒绝分布相等）或 `Pass`（未拒绝）；论文的显著性水平为 $\alpha=0.05$。
- **内部机制**：判断两个来源的输出是否像是从同一个条件分布中采样。MET 的原始研究主要基于分布差异统计量（如 MMD）进行假设检验；本论文直接采用该现有框架，给出不同任务上的拒绝/未拒绝结果。
- **设计目的**：模型身份相同却改了推理预算、截断或提示词预处理时，指纹仍可能相符，而输出分布检验仍可能发现异常。

**C. 元数据：侧信号审计（§5.4）**

- **输入**：请求时延、总 token 数、重复测量的离散程度。
- **输出**：Shadow 与 Official 的标准差之比；记录超出阈值的波动样本。
- **逻辑**：一个多级代理可能存在额外排队、重试、不同后端路由或输出截断。但时延受网络环境与负载影响，因此**元数据只是一条侧面佐证，不足以直接判定谁是真正模型**。

**D. 受控真值验证（§5.3）**

作者还搭建六个自己知道真实后端的端点：三个诚实端点与三个悄悄替换的端点。替换方式包含：

| 声称的模型 | 受控替换后的真实模型 | 对应问题 |
|---|---|---|
| GPT-5 | GLM-4-9B | 跨家族替换 |
| Gemini-2.0-flash | Gemini-2.5-flash | 同家族版本不符 |
| DeepSeek-Reasoner | DeepSeek-Chat | 从推理模式降级为非推理模式 |

这一步很关键：**在真实 Shadow API 上没有后台真值标签时，作者至少让检测流程在一个已知答案的环境里接受了校准。** 当然，校准仅覆盖这三种替换情形，不能证明算法对一切未知模型都有效。

### 3.3 关键公式与算法（Key Equations and Algorithms）

> **公式来源说明**：目标论文主要是一篇实证审计论文，未提出新的端到端训练目标。下面第一个表达式是对其 LLMmap 决策流程的**教学性抽象**，第二个表达式展示所引用 MET 统计检验的原理；二者并非声称是目标论文逐字给出的原创公式。论文明确给出的距离比率阈值、显著性水平及元数据标准差比率，会单独标明。

#### 公式一：把模型身份判断转化为“指纹匹配 + 距离异常”

$$
\hat m = \underset{m\in\mathcal M}{\operatorname{argmin}}\; D\bigl(\phi(R_{\mathrm{shadow}}(Q)),\,\mu_m\bigr),
\qquad
D(u,v)=\lVert u-v\rVert_2.
$$

其中：

- $Q=\{q_1,\dots,q_k\}$：主动选择的一组指纹探针问题。
- $R_{\mathrm{shadow}}(Q)$：影子端点对这些问题返回的响应集合。
- $\phi(\cdot)$：对一组响应形成可比较指纹的表征过程。此处是帮助理解的**抽象记号**，不等于声称论文公开了特定神经编码器架构。
- $\mu_m$：已知候选模型 $m$ 的参考指纹；$\mathcal M$ 是可识别的候选模型集合。
- $\hat m$：最匹配的模型身份，$D$ 是欧氏距离。这里的 $D$ **不是**“属于某模型的概率”，也不是“准确率损失”。

论文在 **Table 3** 使用两个异常条件：① 指纹 top-1 匹配到的模型**不是**对外宣称的模型；② 即便模型名字匹配，距离仍比相应官方基准大 **25% 以上**。可将其决策条件概括为：

$$
\operatorname{Flag}_{\mathrm{FP}}=
\mathbf 1\left[
\hat m\neq m_c
\;\lor\;
\frac{D_{\mathrm{shadow}}}{D_{\mathrm{official}}}>1.25
\right].
$$

**直觉**：指纹类似“模型笔迹”。如果购买的模型是甲，但笔迹最像乙，这是**身份不符的线索**；如果仍最像甲，但与甲的正常样本差得异常远，则是**分布或行为受扰动的线索**。两种告警强度不同，不应该混写为“都确认换模”。

**真实例子（Table 3）**：

- `GPT-5` 经 Shadow API **A/E** 返回的指纹，更接近 `glm-4-9b-chat`。
- `GPT-4o-mini` 经 Shadow API **H** 返回的指纹，更接近 `Qwen2.5-7B`。
- `DeepSeek-Reasoner` 经 Shadow API **A/H** 返回的指纹，更接近 `DeepSeek-Chat`。
- `Gemini-2.5-flash` 在 A/E/H 上**都匹配到正确名称**（其中 A 的距离仍超过阈值），但这并不意味着医疗/法律任务的行为忠实；下面的结果恰好说明这一点。

![论文 Table 3：LLMmap 指纹匹配与欧氏距离](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table3_fingerprints.png)

*表 3（原文 p.9）：红色为匹配到其他模型，黄色为虽匹配到声称的模型但距离超过 1.25 倍官方参考，绿色为身份及距离未触发该阈值。*

#### 公式二：MET 将“是否同一个输出分布”变成统计假设

$$
\begin{aligned}
H_0 &: P_{\mathrm{shadow}}(y\mid x)=P_{\mathrm{official}}(y\mid x),\\
H_1 &: P_{\mathrm{shadow}}(y\mid x)\neq P_{\mathrm{official}}(y\mid x)
\quad\text{（在所评测的任务分布上）}.
\end{aligned}
$$

- $x$ 是任务提示词，$y$ 是模型生成响应。
- $P_{\mathrm{official}}$ 与 $P_{\mathrm{shadow}}$ 是两种黑盒生成过程的条件输出分布。
- 检验统计量越表明两组样本不像同源，就越有可能拒绝 $H_0$。用于理解 MET 的典型分布距离是**最大均值差异**（MMD）：

$$
\mathrm{MMD}^{2}(P,Q)=
\mathbb E_{y,y'\sim P}[k(y,y')]
+\mathbb E_{z,z'\sim Q}[k(z,z')]
-2\mathbb E_{y\sim P,z\sim Q}[k(y,z)],
$$

这里 $k$ 衡量两条响应的相似程度；第 1、2 项是**各自内部相似性**，第 3 项减去的是**跨来源相似性**。如果两组样本来自同一分布，理论上差异应较小。**注意：这一公式说明所引用 MET 方法的一般原理，不代表目标论文披露了它在所有实验中使用的确切核函数、采样量或代码细节。**

实际检验使用显著性水平 $\alpha=0.05$，论文建议采用置换检验得到 $p$ 值：

- $p<0.05$：拒绝分布相等，可说**在被测任务和样本量下存在统计可区分的输出差异**。
- $p\geq0.05$：**未能拒绝分布相等**，不能反过来证明两个端点“必然是同一个后端”。

**关键直觉**：LLMmap 更像“识别笔迹作者”，MET 更像“比较两批文章的语言统计特性”。前者可能指出一个替代模型名称，后者可能发现无法由简单身份判断解释的输出差异。

#### 辅助指标：时延与 token 的离散度比率

论文 §5.4 实际使用的明确公式是：

$$
r=\frac{\mathrm{SD}_{\mathrm{shadow}}}{\mathrm{SD}_{\mathrm{official}}}.
$$

在相同模型与 benchmark 下，分别对**请求时延**、**总 token 数**计算这个 $r$。如果 $r>2$，意味着影子端点的标准差超过官方端点两倍，是值得追查的异常；但 SD 比率本身**不涉及后端身份证明**。注意标准差衡量的是**波动性**，并不是平均耗时，不能将“高 SD”直接理解成“每次都慢两倍”。

#### 算法概览：作者建议的四阶段核验协议（§7）

```text
输入：宣称模型 m、Shadow API endpoint、对应 Official API
1. 指纹：至少 24 个 LLMmap probes
   - top-1 模型名称不符，或 D_shadow / D_official > 1.25 → 告警
2. 分布：在预先定义的任务上运行 MET
   - 置换检验 p < 0.05 → 告警
3. 稳定性：至少 3 个独立 session，在留出任务上复测
   - 准确率 SD > 5% 或时延变异系数 CV > 0.15 → 告警
4. 来源：检查法人、注册信息、法律文件和公开上游说明
   - 缺少可验证主体或链路证据 → 提升运营/合规风险等级
输出：任一阶段告警则按作者建议**避免继续使用该端点**；无告警仍持续监测；发表时披露端点与审计证据
```

**不要混淆两类阈值**：`1.25×` 属于指纹**距离异常**；`2×` 属于论文元数据实验里观察**波动异常**的汇总标准；它们不是一种指标，也不是从同一个统计检验推导出来的。

### 4.1 实验设置（Experimental Setup）

#### 4.1.1 数据集、评估模型和指标

| 目的 | Benchmark / 样本 | 被测模型 | 主要观测指标 |
|---|---|---|---|
| 科学与推理能力 | **AIME 2025**（竞赛数学）；**GPQA Diamond**（高难度科学问答） | 8 个模型 | Accuracy、三次测量的 SD、官方/影子准确率差 |
| 医疗、法律能力 | **MedQA USMLE**（逐题分析中共 **1,273** 道）；**LegalBench SCALR**（逐题分析中共 **571** 道） | 每家族一个代表：GPT-5-mini、Gemini-2.5-flash、DeepSeek-Chat | Accuracy、逐题正确性一致率（Tables 15–16） |
| 有害请求响应 | **JailbreakBench**（100 个行为请求）；**AdvBench** 原始 520 条，实际取 **50 条子集** | 同上 3 个代表模型 | StrongREJECT rubric 下的 mean harmfulness score ± SD |
| 模型身份 | LLMmap 主动指纹探针与 60 个候选模型参考库 | **3 家 × 8 个模型 = 24 个 Shadow 端点** | top-1 模型身份、欧氏距离 $D$ |
| 输出分布 | AIME、GPQA、AdvBench、JailbreakBench | 相应端点和任务配置 | MET：在 $\alpha=0.05$ 下 Reject / Pass |
| 服务质量侧信号 | AIME、GPQA 的调用日志 | 24 个 Shadow 端点，2 个 benchmark | 时延 SD、总 token SD、$r$ 比率 |

8 个模型按家族划分：

- **OpenAI 家族**：GPT-4o-mini、GPT-5、GPT-5-mini。
- **Google 家族**：Gemini-2.0-flash、Gemini-2.5-flash、Gemini-2.5-pro。
- **DeepSeek 家族**：DeepSeek-Chat、DeepSeek-Reasoner。

**Baseline**：对于每个被宣传的模型，直接使用**对应官方 API**。这一点比“和另一个公认强模型比”更重要，因为论文问的是**忠实性（fidelity）**，而不是榜单排名。一个影子端点准确率比官方稍高，也可能是随机方差或发生了某种配置/身份变化，不能简单理解为“影子服务反而更先进”。

#### 4.1.2 控制变量与实施条件

根据 §4.1、Appendix E.1（Table 13）：

- **测量窗口**为 **2025 年 9—12 月**；生态统计、价格等截至 **2025-12-06**。这些是**历史观测快照**，不是 2026 年 11 月仍然有效的实时服务排行榜。
- 任务评估通常进行**三次运行**并报告平均值和标准差；在模型与端点**支持时**设置 `seed=42` 和 `temperature=0`；不支持的参数不强行传入。
- 推理模型使用**默认 reasoning effort**；作者特别说明需要关注服务端对推理参数的支持差异。这里的“默认”并不自动意味着不同中转商在后台设置了同样的思考预算。
- AIME 和 GPQA 使用 **EvalScope** 模板，MedQA 使用 **Hulu-Med** 多选模板，LegalBench 使用原任务 prompt；安全评估 GCG 的后缀在 **LLaMA3-8B** 上生成再迁移到目标模型。
- 效用和安全结果通过 API 请求获得，不需要本地 GPU 推理；LLMmap 参考指纹库的构建使用 **NVIDIA DGX A100**。
- 按论文的选取准则，A/E/H 是**在学术项目里较常见、当时可访问、并且覆盖所测模型**的三个服务商；不是 17 家中的随机样本。

**实验可比性的小陷阱**：Table 13 中某些官方推理模型不支持温度参数（标为 N/A），相应 Shadow API 却显示了固定温度字段。统一 prompt 和尽可能统一配置有帮助，却不能保证中间商实际透传了相同的推理设置。作者后续观察到的异常，正可能部分来自这种不可观测配置差异。

### 4.2 主实验结果（Main Results）

#### 4.2.1 科学推理：越需要推理，越容易暴露“不等价”（Figure 3）

![论文 Figure 3：科学任务准确率对比](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/figure3_utility_science.png)

*图 3（原文 p.6）：AIME 2025 与 GPQA Diamond 上，8 个声称的模型分别经官方与 A/E/H 三家 Shadow API 调用的准确率。误差棒反映重复评测的不确定性。*

原文报告，在科学任务的汇总对比中：

| 服务商 | 与官方相比的平均准确率差距 | 主要特征 |
|---|---:|---|
| **Shadow API E** | **2.64 个百分点** | 总体最接近官方；个别组合影子端点得分略高 |
| **Shadow API H** | **6.46 个百分点** | 在部分推理密集任务上差距放大 |
| **Shadow API A** | **9.81 个百分点** | 整体偏离最大；难推理任务尤其明显 |

其中 AIME 2025 上，**Shadow API A** 相比官方的准确率下滑，在 `Gemini-2.5-pro` 达 **40.00 个百分点**，在 `DeepSeek-Reasoner` 达 **38.89 个百分点**。

**为什么这一结果重要？** 因为影子端点并不是对所有题都糟糕，而是常在简单问答上保持接近官方的表现，到了需要多步推理或严格正确答案的任务才明显掉队。这与**替代模型只具备“表层相似能力”、或高阶推理过程被压缩**的机制一致。

但它**只能验证“复杂任务更容易发现忠实性问题”**，还不能单凭图 3 证明“运营者一定用小模型替换大模型”。所以下一步必须转向 Table 3 的指纹证据。

论文 §5.1 还做了一个有启发性的“替代模型单独评测”：被怀疑对应 `GPT-4o-mini → Qwen2.5-7B` 的替代模型在 **GPQA** 上得分 **42.93%**，官方 GPT-4o-mini 为 **44.61%**，只差 **1.68 个百分点**；但在 **AIME** 上分别为 **3.33%** 与 **14.44%**，差 **11.11 个百分点**。这说明：

> **只有在有区分力的任务上测量，才能使“伪装得像”的模型暴露能力边界。简单 benchmark 的高一致性不能当作身份验证。**

#### 4.2.2 医疗、法律：平均值下滑之外，逐题分歧才真正令人担忧（Figure 4、Table 2、Tables 15–16）

![论文 Figure 4：医疗与法律基准](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/figure4_utility_sensitive.png)

*图 4（原文 p.6）：医学 MedQA 与法律 LegalBench 的准确率比较；这里不仅关系到榜单分数，也对应现实高风险任务的可靠性。*

Shadow API A/E/H 在医疗与法律任务上的平均准确率下降分别为 **16.96 / 15.71 / 14.75 个百分点**。其中最显著的是 **Gemini-2.5-flash**：

- **MedQA**：官方 **83.82%**，三家影子端点平均约 **36.95%**，差距约 **46.87 个百分点**；单端点差距范围约 **46.51—47.21 个百分点**。
- **LegalBench SCALR**：同一模型在三家影子端点上均比官方低 **40.10—42.73 个百分点**。

从 Appendix F 的原始计数出发，结论会更具体。以下是 **Table 15** 中 Gemini-2.5-flash / MedQA / Shadow API A 的第一轮结果：

| 结果类别 | 题数 | 含义 |
|---|---:|---|
| 官方与影子都答对 | 448 | 两者在正确性上没有差别 |
| 官方与影子都答错 | 184 | 两者都失败；**不保证错误答案完全相同** |
| **仅官方答对** | **619** | 使用影子端点会失去本来具备的正确解答 |
| 仅影子答对 | 22 | 影子端点偶尔优于官方 |
| 合计 | **1,273** | 每题属于且仅属于上面四种情形 |

由此可直接复算：

$$
\begin{aligned}
\mathrm{Acc}_{\mathrm{official}} &= \frac{448+619}{1273}\approx 83.82\%,\\
\mathrm{Acc}_{\mathrm{shadow\ A}} &= \frac{448+22}{1273}\approx 36.92\%,\\
\mathrm{Correctness\ Agreement} &= \frac{448+184}{1273}\approx 49.65\%.
\end{aligned}
$$

![论文 Table 15：MedQA 逐题差异](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table15_medqa_detail.png)

*表 15（原文 p.21）：三家 Shadow API 在 MedQA 的逐题正确性四分类结果。*

**这组计数比一个平均准确率更有解释力**：A 的官方独有正确题为 **619**，而影子独有正确题只有 **22**，不是两套模型在不同问题上互有胜负那么简单，而是存在明显的不对称能力损失。类似地，LegalBench 的 **Table 16** 显示 Gemini-2.5-flash 的三家影子端点逐题正确性一致率只有 **52.36%—54.64%**。

![论文 Table 16：LegalBench 逐题差异](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table16_legal_detail.png)

*表 16（原文 p.21）：法律任务的同类四分类统计，便于与医疗任务对照。*

原文 **Table 2** 还给出易于理解的具体失效案例：在一例涉及分娩期严重出血与转院决策的 MedQA 多选题中，官方 Gemini-2.5-flash 在三次运行均选中基准正确答案 **D**，而三家 Shadow API 三次均给出错误答案 **E**。该案例说明差异不是表格四舍五入造成的统计噪声；不过单一案例本身也不支持推断后台一定被换成了哪个模型。

**细节辨析**：原文有时将上述数值称为“answer consistency”，但 Tables 15–16 是按“双方答对/双方答错”的**正确性状态**分类的。即使“双方都错”，二者也可能答出完全不同的错误选项。因此这一指标更严格的中文翻译应为“**逐题正确性状态一致率**”，不要误读为“49.65% 的生成文本完全相同”。

具体看几个关键例子：

- **JailbreakBench / Gemini-2.5-flash / FlipAttack**：官方 harmfulness 约 **0.90**，三家影子端点约 **0.67—0.68**，绝对差约 **0.23**。如果研究者只测影子端点，就可能误以为官方模型更能抵抗 FlipAttack。
- **AdvBench / 同模型、同攻击**：官方约 **0.95**，影子端点约 **0.82**；结论方向与上一数据集一致。
- **JailbreakBench / GPT-5-mini / Base64**：官方约 **0.02**，Shadow A **0.04**；影子端点是官方的两倍。
- **AdvBench / GPT-5-mini / Base64**：官方 **0.01**，Shadow A **0.05**；是五倍，但**绝对差只有 0.04**。

这里最容易产生两种错误解读：

1. “Shadow API 的 harmfulness 更低，因此它比官方更安全”——**不成立**。本文研究的是对指定官方模型的忠实性，不能用一个窄任务上的低分替代对整个服务的安全证明。
2. “风险上升了五倍，所以损害非常大”——需要注意绝对基线 **0.01 → 0.05** 很小；相对倍数在接近零时很容易显得夸张。更应关注攻击类别、绝对差异、方差以及对下游研究结论的影响。

**与方法论假设的关系**：Figures 5–6 证实了“即使使用同名模型，API 入口也是安全评估的干扰变量”。这与论文引言强调的**安全研究可复现性**高度一致。

#### 4.2.4 身份验证：哪些结果更接近“换模证据”？（Tables 3–4）

**Table 3 的统计结论：**

- **11/24 = 45.83%**：指纹 top-1 与声称的模型身份不一致。
- **另有 3/24 = 12.50%**：匹配模型名称一致，但欧氏距离与官方参考相比超过设定阈值。
- **这两类情况不能合并解释为 14 个已经被确证换模的端点。** 第一类才有具体替代模型的候选身份线索；第二类主要是“距离异常”。

例如，`GPT-5` 经 A 和 E 显示出 `glm-4-9b-chat` 的指纹，`DeepSeek-Reasoner` 经 A、H 更像 `DeepSeek-Chat`。如果只是观察准确率下滑，我们无法确定成因；而指纹与某个**具体候选替代模型**一致，则使“后台替代”成为更有根据、也更可检验的解释。不过黑盒指纹仍是概率性证据，不是后端权重的直接取证。

![论文 Table 4：MET 拒绝/未拒绝分布相等结果](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table4_met.png)

*表 4（原文 p.9）：MET 的 `Reject` 表示在 $\alpha=0.05$ 下拒绝官方与影子输出分布相同；`Pass` 仅表示本次测试未拒绝。*

**Table 4 提供了一条互补证据**：例如 `GPT-5` 在 GPQA 上经 A/E/H 均被 MET 判定为与官方输出存在统计差异；`Gemini-2.5-pro` 在 AIME 上三家均为 `Pass`。后者不能写成“证明三家都原样转发了 Gemini-2.5-pro”，正确表述是“在该任务、样本量和检验功效下没有发现足够证据拒绝相等性”。

**一个值得深入研究的反例**：`Gemini-2.5-flash` 在 A/E/H 上，LLMmap 仍把它识别为 `Gemini-2.5-flash`，然而医疗与法律准确率竟出现近乎一致的大幅下滑。作者提出**推理预算被禁用或显著缩减**作为一个合理猜测（§6.1），但并未直接观测到后台 reasoning budget，因此**这不是已经验证的因果机制**。

> 这一反例说明：**“指纹忠实（identity fidelity）”与“行为忠实（behavioral fidelity）”是两件事**。即使确认实际调用了宣称的权重，也不等于确认提示词、上下文、采样配置、思考预算和输出处理链条全都相同。

### 4.3 消融实验与控制性验证（Ablation Studies）

#### 4.3.1 先说明事实：论文**没有**标准的模块消融实验

如果按机器学习论文常见的“移除模块 A/B/C，看总体性能下降多少”来理解消融，本论文**没有提供这种实验**。原因并不奇怪：其创新点在于审计证据链和真实世界测量，而不是可由一个损失函数训练的端到端模型。

因此，**不能杜撰**诸如“去掉 MET 准确率下降 X%”“指纹模块贡献最大”的实验结果。最接近消融思想的证据有三类：

1. **受控后端替换验证**（Tables 5–6）：为测试器提供真值，观察 LLMmap 与 MET 各自能否检出替换。
2. **跨维度结果对照**（Table 10）：同一端点可能通过某种检测，但在其他维度出现风险信号，说明单独依赖一个模块不够。
3. **回归关联分析**（Table 9）：检查指纹距离、价格、身份不符、推理模型标记是否足以解释准确率下降，但它是关联分析，**不是因果消融**。

#### 4.3.2 受控试验：LLMmap 与 MET 谁更容易漏检？（Table 6）

![论文 Table 6：六个真值可知端点上的检测器表现](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table6_validation.png)

*表 6（原文 p.10）：作者在 3 种诚实配置和 3 种替代配置的受控试验台上报告各检测器的准确率、误报率和漏报率。*

| 指标 | LLMmap | MET | 技术含义 |
|---|---:|---:|---|
| 准确率（Accuracy） | **96.00%** | **88.33%** | 在该受控配置集合上，LLMmap 的决策正确率更高 |
| 误报率（FPR） | **3.00%** | **4.67%** | 真实端点未替换，却被误判为不一致 |
| 漏报率（FNR） | **5.00%** | **18.67%** | 实际已经替换，却被当作忠实端点接受 |

具体设置是：**每个受控端点为 LLMmap 提供 $N=100$ 个查询**；MET 使用另一组**600 次请求**进行检验（§5.3）。

**为什么 MET 的 FNR 更高？** 如果替代模型在某些任务上生成的输出分布与官方非常接近，两样本检验就可能没有足够的统计功效；但 LLMmap 的辨识性探针更容易抓到模型的风格/行为差异。这与两个方法设计目标不同相吻合。

**这一结果对方法论的验证力度**：它排除了“检测器本身纯粹乱报”的一种简单解释，增强了真实服务异常结果的可信度；但仅测试三种人工构造的替换，并不能推出“真实世界所有替换的检测准确率都是 96%”。

#### 4.3.3 端点风险汇总与回归：价格不是可靠护身符（Tables 9–10）

![论文 Table 10：四项风险证据汇总](https://win-typora-figure.oss-cn-beijing.aliyuncs.com/%20img-win-1/table10_risk.png)

*表 10（原文 p.13）：FP、MET、Perf、Meta 四项标记聚合到每个端点；这里的对勾代表**触发异常标记**，不是“通过审计”，务必避免误读。*

作者以四个维度的告警数量做汇总：**≥3 项 = High，1–2 项 = Medium，0 项 = Low**。24 个端点中：

- **High：11 个（45.83%）**。
- **Medium：9 个（37.50%）**。
- **Low：4 个（16.67%）**。

A 没有 Low-risk 端点，而 E 的 Low-risk 有 3 个。注意这是一套**描述性风险分箱规则**，不是经过严格概率校准的业务损失概率；四个信号之间也可能存在相关性，不能把“触发 3 个指标”理解成“三项独立证明”。

在 **Table 9**，作者以 24 个端点为样本做 OLS 回归，解释准确率差距：

- 价格比率系数约 $\beta=-1.45$，$p=0.49$；未发现价格可以可靠预测准确率下降。
- 身份不一致指标的 $p=0.98$，总体 $R^2=0.15$；仅靠少数静态解释变量无法很好解释行为退化。
- 移除三个行为异常的 Gemini-2.5-flash 端点后，$R^2$ 提升至约 0.30，身份不符系数变得边缘显著（论文报告 $p\approx0.05$）。

**对作者结论的适当限定**：这支持“在本次测量的样本里，**买贵的并不自动更可信**”，但不代表统计学上已经证明“任何市场、任何时间价格与质量都完全无关”。$n=24$ 太小，而且提供商、模型家族、配置和价格彼此可能混杂。

#### 4.3.4 真正缺少哪些消融？

如果重新设计这篇论文的下一轮实验，我最希望看到：

- **去掉某一审计维度的检测性能**：在规模更大的真实真值试验台上，分别只用 LLMmap、只用 MET、只用性能评测、组合其中两种，报告 Precision/Recall/FPR/FNR 和检测成本。这样才能回答“哪一个模块贡献最大”。
- **指纹探针数量曲线**：8、16、24、50、100 条时的识别准确率与费用，建立成本—检测力折中。
- **推理预算控制实验**：同一官方模型，在不同 `reasoning effort`、输出长度、上下文截断条件下指纹与准确率如何变化；专门验证 Gemini-2.5-flash 的异常机制。
- **跨日期稳定性对照**：同一个端点连续多周每隔固定时间测一次，区分一次性部署故障与系统性/动态替换。

ShadowAPI/

├── safety/        # JailbreakBench / AdvBench、攻击与 StrongREJECT 评分

README 给出的基本复现实验方式可概括为：

```bash
pip install -r requirements.txt
python utility/dataset/prepare_datasets.py

# 官方基准
python utility/run_eval.py --endpoint official --benchmark aime2025 --model GPT-5-Mini

# 使用研究者有权限评估的独立测试端点（以下地址仅为占位符）

  --base-url https://your-endpoint/v1 --model-id YOUR_MODEL_ID --label ep1

# 汇总并进行分布检验
python utility/aggregate_results_utility.py --shadow-label ep1
python fingerprint/met/run_met.py --shadow-label ep1
```

公开仓库的 README 还说明：默认执行**三轮完整 benchmark**，并拒绝仅收集一轮的设置，避免 MET 因样本不足产生误导性拒绝结论。某些基准数据需要按其授权方式单独获取。

**严格区分两层复现性**：

1. **方法复现**：可以使用公开代码，在你有权测试的端点上重新开展相同类别的效用、安全、指纹和 MET 审计。
2. **论文数字精确复现**：公开仓库没有提供 A/E/H 的完整原始结果、识别用的全部第三方端点及当时的后台环境。即使今天运行同样代码，也不保证能精确复现 2025 年的论文数字。

这是值得向作者追问的点：出于伦理、法律和对受影响研究者的保护，作者选择限制发布非匿名数据（Appendix A/B/C）。这种保护可以理解，但也会降低外部审计者**独立验证该研究特定数字**的能力。

#### 4.4.2 如果自己要做一次可信的 Shadow API 审计

建议额外记录以下字段，以免复现时缺少关键上下文：

| 字段 | 作用 |
|---|---|
| 完整 endpoint URL、供应商标识和声称模型版本 | 保证日后知道测量的是谁、哪一个模型 |
| UTC 请求时间、请求 ID、HTTP 状态码 | 识别限流、异常时段、错误重试和服务版本漂移 |
| temperature、seed、top-p、reasoning effort、max tokens 等**实际接受的参数** | 分辨配置不一致和模型不一致 |
| 原始响应、评审输出、token 计数、时延 | 检查截断、隐藏推理成本、输出格式异常与复测差异 |
| 指纹匹配模型、$D$、官方 $D$、MET $p$ 值 | 保存独立于准确率的身份/分布审计证据 |
| 每次运行的指标及方差 | 避免用一个看似稳定的平均数掩盖异常波动 |

**可执行性原则**：使用官方渠道或已经获得授权的测试端点；不要因为发现某种第三方服务就默认其转售、地域访问或数据处理方式是合规且安全的。对于企业或含敏感数据的实验，不应把真实医疗记录、生产密钥或未公开数据送到不透明的中转服务。

## 5. 讨论与思考（Discussion and Reflection）

### 5.1 优点与创新点（Strengths & Innovations）

**① 研究问题抓住了科研基础设施的“隐藏信任假设”。** 过去不少研究把 `model="gpt-5"` 当作实验元数据中的事实，但模型名称是用户提交的**路由标签**，不等于得到后端权重或服务商的真实性证明。本文把这一默认前提变成可质疑、可实测的研究对象，具有很强的现实价值。

**② 证据链有层级，且有意识避免过度因果归因。** Figure 3/4 提供能力下降，Figure 5/6 提供安全行为差异，Table 3 提供替代身份候选，Table 4 提供统计独立检验，Table 6 提供受控校准，Tables 7/8 提供服务侧信号。每一层既相互支持、又承认不能替代其他层。尤其是论文 §2.3 主动区分**行为偏离、身份不符、欺骗性商业主张**，比“一看到分数不同就说商家换模”的叙事更严谨。

**③ 案例选得有启发性：既有明显换模线索，也有“身份正确但能力塌缩”的反例。** Gemini-2.5-flash 的现象提示我们：可信 LLM 服务至少要核验两个对象——**backend identity** 与 **inference configuration / behavior**。如果只做模型指纹，很可能遗漏更隐蔽的推理预算降级。

**④ 受控验证和开源工具让结果不仅是‘爆料’。** 六个已知真值端点的受控实验（Table 6）提供了误报/漏报的量化信息，公开仓库允许研究者将类似流程应用于自己的可信范围内的系统。

### 5.2 局限性与可商榷之处（Limitations & Debatable Points）

#### 局限一：调查覆盖了 17 家，但深度结果只属于其中 3 家

这是理解 **45.83%** 的第一条红线：分子是 **24 个被测模型端点中的 11 个**，不是 17 家服务商中的 11 家，更不是“整个市场超过四成在故意造假”。三家 A/E/H 按热度、可访问性和模型覆盖筛选，有明显的**方便抽样与幸存者偏差**；停止运营、隐藏得更深或没有学术代码痕迹的服务可能完全不在样本中。作者自己在 §2.3 和 §8 也明确限制了外推范围。

#### 局限二：真实后台没有物理真值，指纹匹配并非密码学证明

LLMmap 的候选参考库只有特定的 60 个模型；如果真实后端是**库外模型、微调蒸馏模型、量化版本、动态多模型混合路由**，top-1 匹配结果可能会把它投射到一个“最接近但并不是真实后端”的候选上。相同的官方模型也可能因版本更新、未知系统提示词或温度设置而改变指纹。

因此，“匹配到 GLM-4-9B”可称为**支持 GLM-4-9B 类替代的指纹证据**，不能据此声称已读取到运营商的服务器配置，或证明经营者具有主观故意。

#### 局限三：MET 对相似替代存在漏报，多个统计检验也需要纠偏

控制试验中 MET 的漏报率为 **18.67%**，已明确说明其边界。另一个值得进一步核查的技术问题是：Table 4 在多个模型、多个任务、多个供应商组合上反复进行 $\alpha=0.05$ 检验。若做很多独立检验而**不说明多重比较处理**，总体误报概率可能高于单次 5%；如果使用 FDR 或家族错误率控制，最终异常端点数可能变化。目标论文没有给出足够详细的检验灵敏度与多重比较分析来彻底排除这种顾虑。

#### 局限四：推理预算降级是有力假设，但还缺关键因果实验

对于 Gemini-2.5-flash，**三家服务商指纹仍像官方模型，医学/法律准确率却近乎同步暴跌**。作者猜测中转商可能在降低思考预算以节省成本；我认为这个解释非常合理，但其他机制也没有排除，例如隐藏的系统提示词、输出长度限制、请求代理重写、模型版本漂移或评测输出解析差异。要做因果归因，至少应该在官方 API 上**人为操控相同的推理预算和截断参数**，检查是否能重现“指纹相似 + 敏感任务失效”的联合现象。

#### 局限五：风险聚合与经济论证有启发性，但不是强统计因果证据

Table 10 把四种告警信号等权计数，缺少针对不同告警的基准可靠性、相关性和真实损失的校准。Table 9 的回归样本数只有 **24**，$R^2=0.15$，并不适合据此宣称某个因素在更广市场中没有作用；“更高价格不能保证更高质量”是合理的经验结论，而不是价格与质量在理论上独立的定理。

论文 §6.2 的“若 30% 的 187 篇论文需要重跑，直接成本约 11.5—14 万美元”是**假设性场景推演**，不是对已发生科研损失的实测统计。类似的金钱估算应该与硬性实验发现分开引用。

#### 局限六：测量时效性与开源限制

论文 §8 明确给出 **2025 年 9—12 月**的测量窗口。服务端路由可能随时间变化，部分服务甚至关闭。论文报告到写作时 **17 家中的 4 家已停止运营**，但不能把这一现象归因于研究公开或作者通知造成——作者没有获得这种因果证据（§6.3、Appendix C）。

公开代码不含原始结果、非匿名端点和完整服务侧证据，具有伦理理由，但也意味着第三方对**特定端点具体换模主张**的独立核验空间受限。这种“保护被测对象/用户隐私”与“最大化可复现性”的张力，是安全测量论文需要持续面对的问题。

### 5.3 未来工作与启发（Future Work & Inspirations）

**方向一：从一次性‘验真’发展为持续性的端点漂移监控。** 现在的检查更像拍照；现实服务的后端可能根据时间、用户、请求长度和价格切换。下一步可以构造 $t$ 时刻的指纹与行为特征序列，设计**变点检测（change-point detection）或序贯检验**，用尽可能少的探针发现“今天开始悄悄切换模型”的时刻。需要预先明确误报控制和 API 成本预算。

**方向二：分离‘模型身份’与‘推理配置’，建立二维可信性基准。** 设计一套全因子对照：同一模型在不同推理预算、最大长度、temperature、系统提示词和上下文截断下，分别测指纹与领域性能。最终尝试诊断四类情况：

| 模型身份指纹 | 行为忠实性 | 可能解释 | 后续取证重点 |
|---|---|---|---|
| 匹配 | 匹配 | 与官方相近 | 时间稳定性、运行 provenance |
| 不匹配 | 不匹配 | 替代模型或版本偏离 | 具体后端候选、上游转发记录 |
| **匹配** | **不匹配** | **推理配置/预处理降级** | reasoning effort、截断、隐藏 prompt |
| 不匹配 | 看似匹配 | 能力相近的替代模型 | 更有区分力的自适应任务与探针 |

这一二维分类比“真假模型”二元标签更加贴近现代 LLM 平台的实际复杂性。

**方向三：从输出侧统计验证走向可验证推理基础设施。** 对于自托管、开源权重或可信云环境，可以研究 TEE 远程证明、签名模型清单、哈希版本标识、可审计的路由日志与配置承诺。目标是让“这次响应由什么模型、什么版本、用什么配置产生”具有**可核验来源证据**，而不是只能通过输出推测。闭源模型上是否能公开提供类似身份承诺，仍是有价值的工程研究题。

**方向四：开发更强的、统计校准过的多证据审计器。** 将 LLMmap、MET、行为 benchmark、元数据分别当作具有不同误报率和漏报率的检测器，在更大真值试验台上校准之后，做**置信度融合、成本敏感探针选择与多重比较纠正**。重点是回答：给定 20 美元预算和不超过 50 次请求，怎样最大程度检出“某模型身份不符”或“行为明显降级”？这比仅增加更多 benchmark 更像一个可以投稿的后续方法论文。

**方向五：直接研究 Shadow API 对已有科研结论的影响。** 选择同意复核的公开工作，在**官方端点**上重跑代表性安全攻击成功率、RAG/Agent 决策率或医疗问答结果，量化哪些论文结论会改变以及改变多少。这比假定所有 187 篇使用论文的结果都有问题更加审慎、有解释力。

### 5.4 适合组会讨论、论文复现和后续选题的五个问题

1. **一个端点通过了指纹检测，但医学准确率下降 47 个百分点，究竟应该算“真模型”还是“假服务”？** 我倾向于引入“模型身份可靠性 × 推理行为可靠性”的二维定义，而不是一个真假标签。
2. **在动态路由环境中，单次 MET 的 $p\geq0.05$ 还有多少意义？** 如果端点对 80% 请求调用官方、20% 请求转给廉价模型，最佳检验设计是什么？
3. **指纹测试的候选模型库不完整怎么办？** 是否应增加“未知模型（open-set recognition）”选项，而不是强迫分类为 60 个候选之一？
4. **如何控制审计成本与统计显著性？** 该论文建议至少 24 个 LLMmap probes、三次独立 session；能否用自适应采样减少请求量，同时维持可解释的误报率？
5. **“可复现性”究竟需要记录到什么粒度？** 只公布模型名称、API URL、温度是否足够？是否需要模型快照、推理预算、具体服务链路、请求时间、hash 化输出日志乃至第三方验证报告？

### 5.5 面向研究实践的总结

**这篇论文最重要的启示不是“所有第三方 LLM API 都不可信”，而是：只要研究把一个远程 API 当作具名模型的实验仪器，就必须把它的身份与行为忠实性当作需要验证的前提。**

如果我负责一个依赖在线 LLM 的研究项目，会把以下原则写入实验规范：

- **优先官方 API、明确授权渠道或可验证来源的开放模型**；无上游证明的端点不能自动等同于官方模型。
- 在正式评测前，**同时核验模型指纹和任务级输出**，并在中长期实验中进行重复抽查。
- 在论文中公开**模型版本、endpoint 来源、调用日期、推理参数、指纹结果、分布检验结果与重复实验方差**；无法证明模型来源时，尽量只声称结果描述了“该端点”，而不要直接归因于“官方 GPT-5/Gemini”等模型。

**最终评价**：这是一篇以**真实世界问题选择、系统性测量和多证据交叉验证**取胜的安全研究论文。其最具说服力的部分是 **Figure 4 的高风险领域能力崩塌 + Table 3 的身份匹配异常 + Table 6 的受控检测验证**；最需要谨慎的部分是**真实后台身份仍为黑盒、三家深度测量的外推限制、推理预算降级尚未经因果验证，以及缺少正式模块消融**。
